# Практична робота №21

## Типи даних та області видимості в JavaScript

Робота демонструє підключення зовнішнього JavaScript до HTML, явне й неявне перетворення типів, області видимості змінних та розрахунок замовлення з ПДВ.

## Як запустити

1. Завантажте репозиторій через **Code → Download ZIP** і розпакуйте архів.
2. Відкрийте `index.html` у браузері. Сервер та встановлення пакетів не потрібні.
3. Натисніть **F12** або **Ctrl+Shift+I**, виберіть **Console** та перезавантажте сторінку.
4. Перегляньте дев'ять результатів із типами, загальну вартість замовлення та масив ПДВ. Ці самі обчислені значення відображаються на сторінці.

`script.js` підключено тегом `<script src="script.js"></script>` безпосередньо перед `</body>`.

## Завдання 1 Перетворення типів

Код обчислює кожен вираз та виводить у консоль саме значення і результат `typeof`. Таблиця нижче пояснює очікувані результати; для захисту роботи слід також переглянути фактичний вивід у Console.

| Вираз | Результат | `typeof` | Пояснення |
| --- | --- | --- | --- |
| `"10" + 5` | `"105"` | `string` | Наявність рядка спричиняє конкатенацію; 5 перетворюється на `"5"`. |
| `"10" - 5` | `5` | `number` | Віднімання перетворює числовий рядок на число. |
| `"10" * "2"` | `20` | `number` | Множення перетворює обидва рядки на числа. |
| `10 + true` | `11` | `number` | В арифметичному додаванні `true` перетворюється на 1. |
| `10 + false` | `10` | `number` | В арифметичному додаванні `false` перетворюється на 0. |
| `Number("125 грн")` | `NaN` | `number` | Увесь рядок із текстом `грн` неможливо перетворити на число. `NaN` належить до типу `number`. |
| `Number("")` | `0` | `number` | Явне числове перетворення порожнього рядка дає 0. |
| `Boolean("false")` | `true` | `boolean` | Будь-який непорожній рядок є truthy незалежно від його тексту. |
| `Boolean("")` | `false` | `boolean` | Порожній рядок є falsy. |

## Завдання 2 Замовлення та ПДВ

Вхідні ціни задано **без ПДВ**. Окрема спільна ставка `vatRate = 0.20` є навчальним значенням. ПДВ додається зверху:

```text
вартість позиції без ПДВ = ціна × кількість
ПДВ позиції = вартість позиції без ПДВ × ставка
загальна вартість = сума вартостей позицій разом із їхнім ПДВ
```

Грошові результати округлюються до двох знаків після коми.

| Товар | Ціна, грн | Кількість | Без ПДВ, грн | ПДВ, грн | З ПДВ, грн |
| --- | ---: | ---: | ---: | ---: | ---: |
| Клавіатура | 1250 | 2 | 2500 | 500 | 3000 |
| Миша | 650 | 1 | 650 | 130 | 780 |
| Кабель USB | 180 | 3 | 540 | 108 | 648 |
| **Разом** | | | **3690** | **738** | **4428** |

`ItemCostCalculator(price, quantity)` повертає вартість однієї позиції без ПДВ.

`OrderSumCalculator(items, rate, itemVatResults)` послідовно обробляє товари, викликає `ItemCostCalculator`, визначає ПДВ для кожної позиції та **повертає лише одне числове значення** — загальну вартість із ПДВ. Окремі результати ПДВ додаються до явно переданого масиву `itemVatResults`, який посилається на `vatResults` виклику. Це дає змогу отримати масив без глобальних змінних і без повернення об'єкта замість числа. Для повторного незалежного розрахунку слід передати новий порожній масив.

Масив після розрахунку:

```js
[
  { name: "Клавіатура", vat: 500 },
  { name: "Миша", vat: 130 },
  { name: "Кабель USB", vat: 108 }
]
```

## Оголошення та області видимості змінних

Увесь скрипт виконується всередині IIFE — функції, яку викликано відразу після оголошення. Її змінні та допоміжні функції не потрапляють у глобальну область видимості. Директива `"use strict"` також забороняє випадкове створення глобальних змінних через присвоєння неоголошеному імені.

| Змінна або параметр | Де доступні | Чому обрано оголошення та чи змінюється значення |
| --- | --- | --- |
| `expressions` | У тілі IIFE та вкладених функціях | `const`: посилання на масив прикладів не переприсвоюється. |
| `result` | У тілі однієї ітерації першого `for...of` | `const`: для кожної ітерації створюється окреме прив'язування до поточного результату. |
| `orderItems` | У тілі IIFE та вкладених функціях | `const`: посилання на масив товарів не переприсвоюється. |
| `vatRate` | У тілі IIFE та вкладених функціях | `const`: ставка однакова протягом виконання. |
| `vatResults` | У тілі IIFE та вкладених функціях | `const`: посилання зберігається; вміст масиву змінюється через `push`. `const` не робить масив незмінним. |
| `orderTotal` | У тілі IIFE та вкладених функціях | `const`: результат обчислюється один раз і не переприсвоюється. |
| `price`, `quantity` | Лише у `ItemCostCalculator` | Параметри функції: локальні прив'язування, які технічно можна переприсвоїти; у роботі вони не змінюються. |
| `items`, `rate`, `itemVatResults` | Лише у `OrderSumCalculator` та її внутрішніх блоках | Параметри функції; не переприсвоюються. Вміст переданого масиву `itemVatResults` змінюється. |
| `orderSum` | У `OrderSumCalculator` та її внутрішніх блоках | `let`: накопичувач змінюється на кожній ітерації. Після завершення виклику недоступний зовні. |
| `item` у `for...of` | У поточній ітерації циклу розрахунку | `const`: поточний товар не переприсвоюється в межах ітерації. |
| `itemCost`, `vat` у циклі | Лише в блоці поточної ітерації | `const`: проміжні результати обчислюються один раз для кожного товару. |
| `item`, `index` у `forEach` | Лише в поточному виклику функції зворотного виклику | Параметри: поточний товар і його індекс не переприсвоюються. |
| `itemCost`, `vat` у `forEach` | Лише в поточному виклику функції зворотного виклику | `const`: локальні значення для відображення рядка таблиці. Це інші змінні, ніж однойменні змінні циклу розрахунку. |
| `tableBody`, `values` | Лише в `addTableRow` та вкладеному циклі | Параметри: посилання не переприсвоюються; DOM-вузол `tableBody` отримує новий дочірній рядок. |
| `row` | У `addTableRow` та вкладеному циклі | `const`: посилання на створений DOM-рядок не змінюється, але його дочірні елементи додаються. |
| `value`, `cell` | У поточній ітерації циклу в `addTableRow` | `const`: значення та посилання на комірку не переприсвоюються; текст DOM-комірки встановлюється через її властивість. |

`var` тут не використовується: функціональна область видимості не потрібна, а `let` та `const` точніше обмежують доступ до змінних.

## Відповіді на контрольні запитання

1. **Чому скрипт наприкінці `body` або з `defer` безпечніший?** До його виконання HTML-елементи вже розібрані браузером, тому звернення до них повертає DOM-вузли. Звичайний зовнішній скрипт у `head` без `defer` зупиняє розбір HTML і може виконатися раніше, ніж потрібні елементи буде створено.
2. **Чим відрізняються `+` і `-` для числових рядків?** Якщо один із примітивних операндів додавання є рядком, `+` виконує конкатенацію: `"10" + 5` дає `"105"`. Оператор `-` виконує числове перетворення: `"10" - 5` дає 5.
3. **Що поверне `10 + true`?** Число 11, оскільки `true` у цій арифметичній операції перетворюється на 1.
4. **Чому `Number("125 грн")` дає `NaN`, а `Number("")` — 0?** Перший рядок повністю не відповідає числовому запису, а порожній рядок за правилами числового перетворення дає 0.
5. **Чому `Boolean("false")` дає `true`?** Це непорожній рядок; його зміст не інтерпретується як логічне значення.
6. **Які значення є falsy?** `false`, `0`, `-0`, `0n`, `NaN`, `""`, `null`, `undefined`. У браузерах існує також історичний спеціальний виняток `document.all`. [Довідка MDN](https://developer.mozilla.org/en-US/docs/Glossary/Falsy).
7. **Чим відрізняється область видимості `var` від `let`?** `var` обмежена функцією або глобальною областю, а `let` — найближчим блоком. Блок `if` не обмежує `var`, але обмежує `let`.
8. **Чому небажані зайві глобальні змінні?** Вони створюють ризик конфліктів імен і неочікуваних змін із різних частин програми, ускладнюючи перевірку та супровід.
9. **Коли обирати `let`, а коли `const`?** `const` — коли прив'язування не переприсвоюється; `let` — коли переприсвоєння потрібне. Зміна властивості об'єкта або вмісту масиву не є переприсвоєнням змінної.
10. **Що зміниться після перенесення змінної з функції у глобальну область?** Вона стане доступною іншим частинам відповідного середовища виконання та існуватиме довше, що посилює залежності. Для звичайного браузерного скрипта глобальні `let` і `const` не стають властивостями `window`, на відміну від глобального `var`.
